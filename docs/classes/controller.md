# Controller

## Назначение (Purpose)

Класс `Controller` является центральным управляющим компонентом системы сортировки. Координирует взаимодействие между всеми элементами системы, принимает решения о дальнейшей обработке товаров и обеспечивает корректную работу сортировочной линии.

---

## Ответственность (Responsibilities)

Класс `Controller` отвечает за:

- управление процессом сортировки;
- получение информации от оборудования;
- обработку событий системы;
- взаимодействие с WMS;
- назначение маршрутов товарам;
- управление конвейерами;
- управление буферами;
- возврат товаров из буферов в основной поток;
- координацию работы сортировщика;
- обработку ошибок;
- передачу товаров на ручную обработку;
- регистрацию событий системы.

## `process_sorter_event()`

Метод `process_sorter_event()` обрабатывает событие датчика, расположенного перед сортировщиком, и координирует передачу товара в `Sorter`.

### Параметры

| Параметр | Тип | Описание |
|----------|-----|----------|
| `sensor_event` | dict | Событие, полученное от Sensor |
| `item` | Item | Товар, обнаруженный датчиком |
| `sorter` | Sorter | Сортировщик, который должен обработать товар |

### Алгоритм работы

1. Проверяет наличие события от датчика.
2. Проверяет соответствие `item_id` события идентификатору товара.
3. Проверяет наличие назначенного маршрута в `item.destination`.
4. Если маршрут отсутствует — отправляет товар на ручную обработку.
5. Передает товар в `Sorter` через `accept_item()`.
6. Если `Sorter` не может принять товар:
   - пытается отправить товар в доступный `Buffer`;
   - если буфер недоступен — отправляет товар на ручную обработку.
7. Передает назначенное направление в `Sorter` через `sort_item()`.
8. Если сортировка невозможна — отправляет товар на ручную обработку.
9. Передает товар дальше через `sorter.send_item()`.
10. Находит выходной контейнер, соответствующий `item.destination`.
11. При успешном помещении товара в `OutputBin`:
    - переводит товар в состояние `SORTED`;
    - обновляет его местоположение;
    - регистрирует успешную сортировку в `Statistics`.
12. Если выходной контейнер не может принять товар:
    - пытается отправить товар в `Buffer`;
    - при невозможности использования буфера отправляет товар на ручную обработку.

### Возвращаемое значение

- объект `Item` — если товар успешно помещен в выходной контейнер;
- `None` — если автоматическая обработка не может быть продолжена.

### Ограничения

Метод `process_sorter_event()` не должен:

- самостоятельно выбирать направление сортировки;
- повторно запрашивать маршрут у WMS;
- изменять характеристики товара;
- выполнять физическую сортировку вместо `Sorter`.

Направление сортировки берется из уже установленного значения:

`item.destination`

которое было получено ранее через цепочку:

`Scanner → Controller → WMS → Controller → Item`

## `release_from_buffer()`

Метод `release_from_buffer()` извлекает товар из временного буфера и пытается вернуть его в основной автоматический поток сортировочной системы.

### Параметры

| Параметр | Тип | Описание |
|----------|-----|----------|
| `buffer` | Buffer | Буфер, из которого необходимо извлечь товар |

### Алгоритм работы

1. Запрашивает следующий товар из `Buffer` через `release_item()`.
2. Если буфер пуст — завершает обработку.
3. Перебирает доступные конвейеры.
4. Пытается передать товар на конвейер через `accept_item()`.
5. При успешной передаче:
   - запускает конвейер;
   - переводит товар в состояние `MOVING`;
   - обновляет местоположение товара;
   - возвращает объект товара.
6. Если ни один конвейер не может принять товар:
   - пытается вернуть товар обратно в тот же буфер;
   - возвращает товару состояние `BUFFERED`;
   - обновляет его местоположение.
7. Если товар невозможно вернуть в буфер — отправляет его на ручную обработку.

### Возвращаемое значение

- объект `Item` — если товар успешно передан на конвейер;
- `None` — если буфер пуст или товар не удалось вернуть в основной поток.

### Ограничения

Метод `release_from_buffer()` не должен:

- повторно запрашивать маршрут у WMS;
- изменять назначенное направление товара;
- самостоятельно перемещать товар;
- изменять характеристики товара.

Товар, находящийся в буфере, уже имеет ранее назначенный маршрут в:

`item.destination`

Поэтому повторный запрос маршрута у WMS не требуется.

## Алгоритм работы

1. Получает сигнал о новом товаре.
2. Регистрирует поступивший товар.
3. Запрашивает сканирование.
4. Получает штрихкод.
5. Отправляет запрос в WMS.
6. Получает направление.
7. Проверяет доступность маршрута.
8. Передает товар доступному конвейеру.
9. Если конвейер недоступен, пытается отправить товар в буфер.
10. Если товар находится в буфере, после появления доступного конвейера возвращает его в основной поток.
11. Контролирует прохождение товара через датчики.
12. Получает сигнал датчика перед сортировщиком.
13. Передает товар и назначенное направление в Sorter.
14. После успешной сортировки передает товар в соответствующий OutputBin.
15. При успешном помещении товара в OutputBin завершает автоматическую сортировку товара.
16. При невозможности продолжить автоматическую обработку пытается использовать Buffer.
17. Если автоматическая обработка невозможна — отправляет товар на ручную обработку.
18. Обрабатывает ошибки при необходимости.
19. Обновляет статистику.

---

## Возможные ошибки

- не удалось считать штрихкод;
- сканер недоступен;
- отсутствует маршрут;
- направление недоступно;
- сортировщик недоступен;
- направление не поддерживается сортировщиком;
- заполнен выходной контейнер;
- отсутствует выходной контейнер для назначенного направления;
- переполнен буфер;
- невозможно вернуть товар из буфера в основной поток;
- недоступен конвейер;
- отсутствует связь с WMS.

---

## Ограничения

Класс `Controller` не должен:

- хранить характеристики товара;
- самостоятельно сканировать штрихкод;
- самостоятельно перемещать товар;
- самостоятельно выполнять физическую сортировку;
- самостоятельно выбирать направление вместо WMS;
- повторно запрашивать маршрут для товара, уже имеющего `destination`;
- принимать функции WMS;
- хранить статистику вместо класса Statistics.

## Примечания

`Controller` является центральным координатором системы. Он не выполняет физические операции самостоятельно, а организует взаимодействие между всеми компонентами сортировочного комплекса.

Метод `process_sensor_event()` используется для обработки события датчика на этапе сканирования и получения маршрута товара.

Метод `process_sorter_event()` используется для обработки события датчика перед сортировщиком. `Controller` передает в `Sorter` уже назначенное направление из `item.destination`. Сам `Sorter` не выбирает маршрут товара.

Метод `release_from_buffer()` используется для повторного включения временно задержанного товара в основной поток. При этом существующее значение `item.destination` сохраняется, и повторный запрос маршрута у WMS не выполняется.
